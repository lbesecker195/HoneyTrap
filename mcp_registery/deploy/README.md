This directory holds the deployment tooling for the production host, not application code. `build-release.sh` packages a linux/amd64 Phoenix release with the project Dockerfile. `deploy.sh` is the single script run from a local terminal to ship that release, provision a new host, and load config from `deploy/.env` (`.env.example` documents each variable, including the Seriously Simple Analytics project id). `remote-install.sh` runs on the server as root, creating its system user and database, installing the systemd service, and configuring the nginx site and its certbot certificate; it requires nginx, certbot, and PostgreSQL already installed and fails otherwise. `receive-release.sh` installs an uploaded release, health-checks it, and rolls back on failure. `mcp-registry.service` is the systemd unit keeping the Phoenix app running, memory-capped since the box is shared with other sites. `nginx-site.conf` is the reverse-proxy template, with the websocket upgrade headers LiveView needs, that certbot later extends for HTTPS.

Pushes to `main` deploy through CI automatically; these scripts exist for first-time host setup, manual redeploys, and config changes.

No file here renders or drives the content of any single page, so no page link is forced here: this is infrastructure that keeps the whole site running rather than code behind a specific route.
