This folder holds two small supporting pieces for the official-registry mirror defined in `lib/mcp_registry/official_registry.ex`: `scheduler.ex`, a GenServer that wakes up and runs a sync at the configured interval (backing off 15 minutes after a failed attempt, and basing timing on the last recorded run so deploys don't trigger extra syncs), and `sync_run.ex`, the Ecto schema for the `registry_syncs` table that records each run's mode, status, stats and errors for troubleshooting.

Together they keep the roughly 31,000 mirrored listings from registry.modelcontextprotocol.io up to date without manual intervention. Every server card in [MCP server search](https://ai.mcpharbor.dev/) and every install-snippet page such as [the Context7 listing](https://ai.mcpharbor.dev/servers/io.github.upstash%2Fcontext7) depends on this sync having run recently and successfully — a stalled scheduler or a failing run means stale or missing servers site-wide, including in the `/api/v0` responses and `llms.txt` feed that agents read.
